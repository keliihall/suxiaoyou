# 苏小有 v1.1.1-rc.2 发布说明

发布日期：2026-07-30

`v1.1.1-rc.2` 是应用版本 `1.1.1` 的第二个候选测试版。它继续使用
`UNSIGNED-DEGRADED` 发布配置，公开为 prerelease、不会标记为 latest，也不代表已经满足正式发行所需的
发行方签名、Apple 公证、authoritative Office renderer、真实集成或受控 Beta 证据。

## 本次修复

- 沿用并验证现有界面防线：未选择明确工作区时，右侧工作栏不会请求或展示“版本与恢复”和“Office 模板”
  可选控制面，避免把正常的 folderless/managed 会话显示成两个黄色错误卡片。
- checkpoint API 现在能正确验证应用创建的 managed workspace，不再把会话目录占位符 `.` 与托管目录
  绝对路径直接比较并误报 provenance 冲突。
- Office 模板 API 按界面语言返回稳定、无路径的错误信息；前端按机器错误码映射中英文文案，不再直接展示
  `The request is not bound to the current verified workspace` 等后端原始诊断。
- 模型 Provider 的流式连接中断会进入统一的重试路径。重试耗尽后只向界面发送稳定错误码和本地化提示，
  原始 `incomplete chunked read` 等底层诊断仅保留在服务端日志。
- 前端记录已经收到 `DONE` 或 `AGENT_ERROR` 的流。在后端从 active job 列表移除任务前，不会重新订阅
  同一个终止流，因此不会重复回放错误并堆叠大量 toast。
- 未知任务错误、上下文压缩、批量任务、聊天发送与编辑重发统一使用稳定错误码和本地化兜底，后端异常
  文本不再直接进入界面或系统通知。
- 远程端在异步轮询、启动恢复和移动端直连入口都会检查终止流标记；远程 SSE 只有收到有效事件后才重置
  重试预算，反复出现 `200 + EOF` 时会有界停止。
- DOCX、XLSX、PPTX、PDF、图片、媒体及通用文件预览失败时统一显示本地化安全兜底，原始文件路径和
  底层异常只写入调试日志。
- 文件版本错误、远程连接状态和离线提示已补齐中英文文案，接口失败不会再把原始英文 detail 显示给用户。

## 六个原生目标、八个安装包

本标签继续从同一提交构建 Windows x64/ARM64、macOS x64/ARM64、Linux x64/ARM64 六个原生目标。
Linux 每个架构同时提供 DEB 与 RPM，因此 GitHub Release 应精确包含八个安装包：

| 平台目标 | 安装包 |
|---|---|
| Windows x64 | `suyo-1.1.1-rc.2-windows-x64-setup-UNSIGNED-DEGRADED.exe` |
| Windows ARM64 | `suyo-1.1.1-rc.2-windows-arm64-setup-UNSIGNED-DEGRADED.exe` |
| macOS Apple Silicon | `suyo-1.1.1-rc.2-macos-aarch64-UNSIGNED-DEGRADED.dmg` |
| macOS Intel | `suyo-1.1.1-rc.2-macos-x64-UNSIGNED-DEGRADED.dmg` |
| Linux x64 | `suyo-1.1.1-rc.2-linux-amd64-UNSIGNED-DEGRADED.deb`、`suyo-1.1.1-rc.2-linux-x86_64-UNSIGNED-DEGRADED.rpm` |
| Linux ARM64 | `suyo-1.1.1-rc.2-linux-arm64-UNSIGNED-DEGRADED.deb`、`suyo-1.1.1-rc.2-linux-aarch64-UNSIGNED-DEGRADED.rpm` |

## 发布信任边界

- Windows NSIS 没有 Authenticode 发行方签名。
- macOS 应用仅为 ad-hoc 签名；DMG 没有 Developer ID 签名、Apple 公证或 staple。
- Linux DEB/RPM 没有包签名或仓库签名。
- Windows ARM64 的 Cloudflare Quick Tunnel 限制、Office restricted compatibility 和其他降级能力
  与 `v1.1.1-rc.1` 相同。

请使用同一 GitHub Release 中的 `CHECKSUMS.md` 和 `release-manifest.json` 校验下载文件。机器可读清单会将
上述信任与能力限制固定到 `v1.1.1-rc.2` 标签和对应的完整 Git commit。
